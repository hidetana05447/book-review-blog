# 書評サイト挿絵制作（book-review-illustration）

汎用Skill `.claude/skills/creative-director/`（secretaryリポジトリ直下）の派生版。**プロセス自体は汎用版に準拠する**（依頼の入り方・AIっぽさ排除の大原則・画像生成AIとの相性・完成条件などはすべて汎用版を参照）。このSkillが追加で持っているのは、2026-08-19に書評サイト記事3本（ヒカルの碁／豊臣秀長／カウンセリングとは何か）の挿絵制作を通じて確立した、**このサイト専用のビジュアル方針**（汎用版でいう`brand.md`に相当するものを、案件ごとに作り直さず固定値として持っておく）。

## 確立済みのビジュアル方針（このサイトの挿絵における brand.md 相当）

- **画風**：半写実的な水彩・ガッシュ画調のエディトリアルイラスト。フラットなベクター調は使わない（2026-08-19、抽象的なフラット図解を3回試して低品質だった一方、絵画的な情景描写は高品質だったため）
- **配色**：クリーム〜アイボリー系の背景（`#faf8f5`系、サイトのサムネイルと同系統）、黒〜焦げ茶（`#2b2b2b`系）、琥珀色のアクセント（`#a8763e`系、サイトのジャンルタグと同色）。鮮やかな原色・ネオン・青紫ティール系の色は使わない
- **構図のアプローチ**：抽象的な関係性の図解（円・シルエット等で概念を象徴させる表現）は避け、**記事自身がすでに使っている具体的なメタファーを、情景として描く**（例：ヒカルの碁→碁盤、豊臣秀長→光と影、カウンセリングの記事→地図と実地）。方向性確認の段階で、まず記事本文の中に転用できるモチーフがないかを探すことを最優先にする
- **人物・手は描かない**（安全策。これまでの3本とも無人の情景で成立している）
- **寸法**：1200×750px、PNG、文字なし（記事本文中に挿入する想定。サムネイル・OGP画像とは別物で、`images/thumbnails/`ではなく記事内の任意の位置に挿入する）
- **実在の書影・実在人物は使わない**（`website/CLAUDE.md`のサイト全体方針に準拠）

## 進め方（簡易モードがデフォルト）

記事1本につき挿絵1枚、という規模感なので、汎用版の「簡易モード」をデフォルトで使う（project folder・request.md等は作らず、会話内で完結させる）。

1. 対象記事のURLを開き、本文を読む
2. 記事の中にある具体的なメタファー・モチーフを探す（上記「構図のアプローチ」参照）。見つかったら、それをベースに2〜3個の情景案を会話内で提示する。見つからない場合のみ、抽象的な表現も含めて再検討する
3. 人間が方向性を選んだら、上記「確立済みのビジュアル方針」（画風・配色・寸法）に沿って、Subject/Setting/Style/Composition/Lighting/Color/Mood/Negativeの構造化プロンプトを組み立てて提示する
4. 人間がGPT Image等で生成し、結果を見せてもらう
5. 汎用版の「画像生成AIとの相性」（完全に一致する図形の重なりを避ける、繊細すぎる象徴的ディテールに頼らない等）と「AIっぽさ排除の大原則」を、頭の中のチェックリストとして適用する
6. 小さな修正が必要な場合は、ゼロからの再生成でなく、既存画像への編集依頼を優先する（汎用版「制作の振り分け」参照）
7. 完成したら、記事のどの位置に挿入するか（見出しの直後、記事末尾等）を人間に確認し、`reviews/<slug>.html`へ`<img>`タグとして追加する（`alt`属性を必ず入れる）

## 汎用版との関係
- スタイル・配色・アプローチはこのSkillが固定値として持つため、`creative-director`の「方向性確認ステップ」のうち**スタイルに関する確認は省略してよい**。ただし「どのメタファー・情景にするか」という内容面の方向性確認は、記事ごとに異なるので毎回行う
- `direction.md`のような正式なファイルは、簡易モードのため作らない。方向性の選択結果は、この会話のやり取りそのものが記録になる
- 今後この方針自体を変えたくなったら（例：画風を変える）、汎用版を直接編集するのではなく、このSkillの「確立済みのビジュアル方針」を更新する
